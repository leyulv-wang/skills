# 项目 Skill 写作指南

这份指南用于写作与编辑 Skill 文档。先确认读者、文档用途和仓库约定。项目材料提供业务规则和工作流程。改写可以调整措辞、标题、段落和内容位置。涉及业务判断、执行顺序、工具契约或权限的变化，标明影响并交给项目确认。

## 写入口

1. **写清触发说明。** 按项目约定填写 `name` 和 `description`。说明能做什么、什么任务适合使用。
2. **交代任务。** 开头用一小段说明输入、处理范围和交付物。把每次都要遵守的约束留在入口或对应步骤旁。
3. **组织已有流程。** 按项目已确认的顺序组织正文。把分支条件、对应动作和需要读取的文件放在一起。
4. **说明如何收尾。** 写清完成条件、必要检查和失败处理。涉及人工确认时，标明确认发生在哪一步。

## 决定内容放在哪里

| 内容 | 位置 |
| --- | --- |
| 每次必读的任务范围、主流程和共用约束 | `SKILL.md` |
| 特定场景才读的规则、长示例和字段说明 | `references/` |
| 可重复执行的提取、转换或校验 | 现有工具，或按需放入 `scripts/` |
| 生成交付物时使用的模板或素材 | 按项目约定放入 `assets/` |

按实际阅读时机拆分。每条规则选一处维护。分支入口写清何时读、要核对什么。使用相对路径直接链接到所需文件。长参考在开头放目录。单一流程能在入口写清时，一个文件即可。

## 统一 Markdown

优先沿用仓库规范。没有明确约定时，采用以下写法。

- 正文用一个一级标题，主节用二级标题，小节用三级标题。标题直接写动作或问题。
- 依次执行的步骤用编号，并列约束用无序列表。表格用于简短对照，复杂例外用小节。
- 文件、字段和工具名用行内代码。多行示例用带语言标识的围栏代码块。标题、列表、表格和代码块与相邻正文之间留空行。

## 逐条核对原文

改写前，从原文列出可单独核对的规则。每条保留触发条件、要求或禁止的动作，以及结果或后续去向。字段、阈值、例子和原文明确区分的状态也列入核对范围。

改写后，将每条原文规则对应到新稿中的一句或一处。尤其核对异常、禁止、例外和回退分支。若原文明确禁止某个推断，改写中仍要明确写出该禁止条件。遇到遗漏、语气变弱、条件合并或新增结论时，先修正再交付。原文含义不清时保留疑问并标记待确认。需要留核对记录时，读[原文核对与复测记录](references/workflow-review.md)。

## 审阅与验证

- **静态检查。** 核对文件头、标题、路径和目录锚点。
- **行为检查。** 新建 Skill 或改变触发、指令顺序、参考读取时机时，验证受影响路径。可以用 `writing-skills` 设计基线和对照案例。只调整 Markdown 样式时，静态检查即可。
- **交付。** 给出 Skill 入口和相关文件，说明哪些只是静态核对，哪些已有实际运行结果。
