# 结构与排版示例

## 选一种适合任务的结构

- **单一流程。** 一份入口写任务、步骤和输出。例如导入前检查 CSV 格式，统一读取、检查、报告三步即可。
- **多分支。** 入口写共用流程和选择条件。各分支的专用材料放在各自文件中。例如合同分析分别查付款约定和续签约定。
- **带执行工具。** 入口交代何时运行已有脚本、传什么参数、看哪个结果。细节留在脚本说明或工具文档中。

## 认款 Skill 组织示例

原入口的「判断与完成」把金额判断、复核工具、多目标例外和展示文案放在同一节。可以顺着实际操作拆成下面的标题。

```markdown
# 认款建议
## 选择用途与查证
### 查证代付
## 判断用途、归属和付款范围
### 确定本次分配额
## 生成建议并调用复核
### 处理多目标分配
## 处理复核结果并返回建议
```

入口可以保留每笔流水都需要的证据与金额约束。代付触发位置链接到共用代付说明，各用途文件写自己涉及的目标、凭证和例外。此例用于说明信息的放置方式，实际条件以项目原有规则为准。若只授权调整排版，保留原句和原有先后顺序。

## 用条件写清链接时机

把「详见更多文档」换成能执行的句子。例如「当任务是提取续签条款时，读续签参考，核对通知期限和生效条件」。审阅时从用户场景走一遍，查看只读入口和命中的参考是否足以完成任务。
